# Otodecks

A two-deck DJ application built with JUCE. Load tracks onto either deck, mix
them, set hot cues, record your output, trigger samples, and detect tempo.

## Features

**Decks** — two independent players, each with play/stop, volume, playback
speed, a draggable position slider that tracks the playhead, and a waveform
display. Files can be dragged straight onto a deck.

**Music library** — a searchable table of tracks with duration and BPM. The
library is written to disk on every change, so it is exactly as you left it
when you reopen the app. Tracks whose file has since been moved or deleted are
dropped on load rather than shown as rows that cannot play.

**Hot cues** — four cue slots per deck. Click an empty slot to store the current
playhead position, click a set slot to jump to it, alt-click to clear one, or
CLEAR ALL to empty the row. Cues belong to the track, so they persist with it.

**Recording** — record either deck in isolation, or the microphone, to a `.wav`
file. Finished recordings are added to the library automatically, and clicking
the saved path in the status bar reveals the file in Finder or File Explorer.

**Loop sampler** — a separate list of short samples. Preview them, send one to
either deck, and loop them. Samples added through the interface are copied into
the app's samples folder so the set survives the original file moving.

**BPM detection** — select a track and press BPM. Tempo is estimated from the
audio via an onset-strength envelope and autocorrelation, cross-checked against
inter-onset intervals to avoid half- and double-tempo errors.

## Requirements

- **JUCE 7 or newer** — JUCE 8.0.4 is what this was developed and tested
  against. Older versions will not compile: the recorder uses
  `audioDeviceIOCallbackWithContext` (JUCE 7+) and the sampler uses
  `RangedDirectoryIterator` (JUCE 6+).
- A C++17 compiler.

## Building

### CMake (CLion, or the command line)

JUCE is located automatically, in this order:

1. `libs/JUCE` inside the project
2. `../JUCE` alongside the project
3. otherwise, fetched from GitHub at configure time (JUCE 8.0.4)

Override with `-DJUCE_PATH=/path/to/JUCE`.

```
cmake -B build
cmake --build build
```

In CLion, open the project folder directly — `CMakeLists.txt` is detected
automatically.

### Projucer (Xcode or Visual Studio)

Open `OtoDecks.jucer` in Projucer, set the global JUCE modules path to a JUCE 8
checkout (every module uses the global path), then save and open the generated
project.

Both build systems reference the same files in `Source/`, so they do not drift.
If the Projucer build fails where CMake succeeded, diff the module list and the
preprocessor definitions before looking at the code.

## Where your data lives

| | |
|---|---|
| macOS | `~/Library/Application Support/Otodecks/` |
| Windows | `%APPDATA%\Otodecks\` |

- `library.json` — the music library
- `sampler.json` — the sample list
- `samples/` — samples copied in through the interface
- `recordings/` — recorded `.wav` files

Deleting these files resets the app to an empty state.

## Source layout

| File | Responsibility |
|---|---|
| `Main.cpp`, `MainComponent` | Application shell, window layout, audio graph |
| `DeckGUI`, `DJAudioPlayer` | One deck: controls and playback |
| `WaveformDisplay` | Waveform and playhead drawing |
| `Track`, `MusicLibrary` | Library data and its persistence |
| `PlaylistComponent` | Library table, search, deck loading |
| `HotCueComponent` | Cue buttons for one deck |
| `AudioRecorder` | Deck and microphone recording |
| `SamplePlayer`, `LoopSampler` | Sample playback and the sample list |
| `BPMAnalyser` | Tempo estimation |
| `PersistenceManager` | Every file path and format decision |

Each deck is rendered into its own buffer and summed by hand rather than through
a `MixerAudioSource`, which is what allows a single deck to be recorded without
the other bleeding in. Disk writing happens on a background thread, so the audio
thread never touches the file system.
